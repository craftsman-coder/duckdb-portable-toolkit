DuckDB Portable Toolkit

A complete, self-contained data and AI environment that runs inside Jupyter and Streamlit. No system Python, no virtual environment, no admin rights required. Just clone and run. Works on Windows, Linux, and macOS — move the folder anywhere and everything still works.

Installation #

The toolkit installs everything inside the project folder: a portable Python interpreter, DuckDB binary, all Python packages, and the AI model. Nothing touches your system.

ℹ
Prerequisites Only one thing is needed: a system Python 3.9+ to run setup.py itself. After that, everything uses the portable Python.

Step-by-step

  1. Clone the repository 
    git clone https://github.com/YOUR-USERNAME/duckdb-portable-toolkit.git
cd duckdb-portable-toolkit
  2. Run the setup script You'll be asked to choose an installation profile. 
    python setup.py
  3. Verify installation 
    python verify.py
    All checks should show [ok]. If any fail, run python setup.py again.
  4. Launch JupyterLab 
    # Windows
start-jupyter.bat

# Linux / macOS / Git Bash
./start-jupyter.sh

Installation Profiles

Choose the profile that fits your needs. You can always re-run setup.py later.

#ProfileIncludesSize
1lightDuckDB + Jupyter + core packages~700 MB
2standard+ visualization + ML + AI + MCP~2.5 GB
3full+ EDA + MLflow + all extensions~5.7 GB
4customLike full, but you edit config firstvaries

Skip the prompt with a flag:

python setup.py --profile standard
✓
One-time internet Internet is needed only during setup to download packages and the AI model. After that, everything works offline.

Launching Apps #

JupyterLab

Three ways to start JupyterLab. Pick whichever is easiest.

Double-click start-jupyter.bat in the project folder.

Double-click start-jupyter.sh, or run it from a terminal:

chmod +x start-jupyter.sh   # first time only
./start-jupyter.sh
# Windows
runtime\python\python.exe -m jupyterlab

# Linux / macOS
runtime/python/bin/python3 -m jupyterlab

After it starts, the terminal prints a URL:

http://localhost:8888/lab?token=594bf1da49163f5649798767c6a9c2c6b73179c7e2059875

Copy the full URL (including the token) and open it in your browser.

!
Choose the right kernel In JupyterLab, click the kernel selector in the top-right and choose DuckDB Toolkit (portable). Without this, import toolkit will fail.

Streamlit Dashboards

The Streamlit launcher shows an interactive menu of all available dashboards:

# Windows
start-streamlit.bat

# Linux / macOS / Git Bash
./start-streamlit.sh

Select a number to launch a specific dashboard, or press Q to quit.

DuckDB UI

An offline web UI for exploring databases visually:

from toolkit.ui import start_duck_ui
start_duck_ui()
# Opens http://localhost:5522

Toolkit Modules #

The toolkit package contains helper functions we wrote to make common tasks simple. Import them in any Jupyter cell.

toolkit.config

Loads config.yaml and exposes all resolved paths.

from toolkit.config import (
    ROOT_DIR, DATA_DIR, EXPORTS_DIR, DUCKDB_EXE, load, paths,
)

print(ROOT_DIR)      # Path to project root
print(DATA_DIR)      # Path to data/
print(DUCKDB_EXE)    # Path to duckdb.exe

toolkit.io_helpers

Simple wrappers for reading and writing common formats.

from toolkit.io_helpers import to_parquet, to_csv, to_qvd, read_any
import duckdb

con = duckdb.connect()
to_parquet(con, "SELECT * FROM sales", "exports/sales.parquet")
to_csv(con, "SELECT * FROM sales", "exports/sales.csv")
to_qvd(con, "SELECT * FROM sales", "exports/sales.qvd")

df = read_any("exports/sales.parquet")

toolkit.parallel

Run multiple DuckDB queries concurrently. Uses one cursor per thread.

from toolkit.parallel import ParallelRunner

with ParallelRunner("db.duckdb", max_workers=4) as runner:
    results = runner.run([
        ("q1", "SELECT * FROM big_table WHERE year = 2024"),
        ("q2", "SELECT count(*) FROM another_table"),
        ("q3", "SELECT avg(amount) FROM orders"),
    ])

for r in results:
    print(r.query_id, r.status, f"{r.elapsed:.2f}s")

toolkit.jobs

Schedule recurring tasks from inside Jupyter (uses APScheduler).

from toolkit.jobs import JobScheduler

scheduler = JobScheduler()
scheduler.add_cron_job(
    "daily_export",
    "jobs/example_daily_export.py",
    hour=0, minute=30,
)
scheduler.start()

# Test immediately
scheduler.run_now("daily_export")

# List scheduled jobs
print(scheduler.list_jobs())

toolkit.ml

Helpers for MLflow tracking and PyTorch utilities.

from toolkit.ml import (
    init_mlflow, track_run, log_regression_metrics,
    split, torch_device, torch_dataloader,
)

init_mlflow("my-experiment")

X_train, X_test, y_train, y_test = split(df, target="y")

with track_run("run-1", params={"lr": 0.001}):
    model.fit(X_train, y_train)
    preds = model.predict(X_test)
    print(log_regression_metrics(y_test, preds))
    mlflow.sklearn.log_model(model, "model")

toolkit.lakehouse

Connect to Iceberg, Delta, DuckLake, Lance, and Paimon.

import duckdb
from toolkit.lakehouse import (
    iceberg_attach, ducklake_attach,
    delta_scan, lance_scan, lance_write,
)

con = duckdb.connect()
iceberg_attach(con, "http://polaris:8181/api/catalog", "lakehouse", alias="ice")
print(con.execute("SELECT * FROM ice.default.orders LIMIT 5").fetchdf())

delta_scan(con, "s3://bucket/delta/orders")
lance_write(con, "SELECT * FROM clean_data", "exports/data.lance")

AI Assistant #

The toolkit includes a fully local AI assistant powered by llama.cpp. No cloud, no API keys, works offline after the initial model download.

💬

Local Chat

Talk to your AI in JupyterLab's chat panel. It can query your database through MCP.

🔌

MCP Integration

Model Context Protocol exposes your tables, schema, and business rules to the AI.

📚

RAG Ready

Give the AI access to your PDFs, Markdown files, and business documents.

⚡

Lightweight

~89 MB binary + 1 GB model. Far smaller than Ollama or other frameworks.

llama.cpp

llama.cpp is a C++ inference engine for LLMs. We chose it over Ollama because it's smaller, faster to start, and easier to keep fully portable. 

from toolkit.ui import start_llama_cpp
start_llama_cpp()
# -> llama.cpp server running at http://localhost:8080

In JupyterLab, open the chat panel from the left sidebar. Then type:

@Jupyternaut What tables are in my database?

Or from Python directly:

import json, urllib.request

payload = json.dumps({
    "model": "qwen2.5-1.5b-instruct",
    "messages": [{"role": "user", "content": "Say hi in Persian"}],
    "max_tokens": 50,
}).encode()

req = urllib.request.Request(
    "http://localhost:8080/v1/chat/completions",
    data=payload,
    headers={"Content-Type": "application/json"},
)
print(json.loads(urllib.request.urlopen(req).read())["choices"][0]["message"]["content"])
from toolkit.ui import stop_llama_cpp
stop_llama_cpp()

MCP Server

The Model Context Protocol server gives the AI read-only access to your DuckDB and exposes business context as resources. The AI can call these tools:

ToolPurpose
query(sql)Run a read-only SELECT query
list_tables()List all tables in the database
describe(table)Get column names and types
business_context()Return your business rules (Markdown)
environment_manifest()Installed packages and extensions
capabilities()What the AI can do in this environment

Business Context

Edit mcp/context/business.md to teach the AI about your data. No restart needed — the MCP server reads it on every request. 

# Business Context

## Tables
### sales
- sale_date: transaction date (Gregorian)
- amount: total in IRR
- status: 'active', 'cancelled', 'refund'

## Rules
- Only status = 'active' counts toward revenue
- Amounts already include VAT

## Common Metrics
- Revenue = SUM(amount) WHERE status = 'active'

Retrieval-Augmented Generation (RAG) #

RAG lets you give the AI access to your own documents: PDFs, Markdown, business rules, SQL schema notes, anything in text form. The AI searches these documents before answering.

ℹ
How it works Documents are split into chunks, embedded with sentence-transformers, and stored in DuckDB with a vector index. Search uses cosine similarity.

Step 1 — Prepare documents

Put your files in data/docs/:

data/docs/
├── business_rules.md
├── schema_notes.md
└── policies/
    ├── returns.md
    └── refunds.md

Step 2 — Build the index

from toolkit.rag import create_index

create_index(
    docs_dir="data/docs",
    table_name="knowledge",
    db_path="runtime/rag.duckdb",
)
# First run downloads the embedding model (~90 MB)

Step 3 — Search

from toolkit.rag import search

results = search("What is our refund policy?", table_name="knowledge", k=5)
for r in results:
    print(f"[{r['score']:.3f}] {r['source']}")
    print(r["text"][:200])
    print("---")

Step 4 — Feed to the AI

from toolkit.rag import build_prompt

prompt = build_prompt("What is our refund policy?", table_name="knowledge")
print(prompt)
# Copy the result into Jupyter AI chat

Offline Installation

Install new packages or extensions on a machine without internet by downloading them on another machine first.

On the internet-connected machine:

from toolkit.maintenance import download_python_package
download_python_package("statsmodels")
# Saves wheels to offline/wheels/

Copy the offline/wheels/ folder to the offline machine.

On the offline machine:

from toolkit.maintenance import install_python_package_offline
install_python_package_offline("statsmodels")

On the internet-connected machine:

from toolkit.maintenance import download_duckdb_extension
download_duckdb_extension("httpfs")
# Saves to offline/extensions/httpfs.duckdb_extension

Copy the .duckdb_extension file to:

runtime/duckdb/extensions/v1.5.5/windows_amd64/

GPU Acceleration

llama.cpp can use your GPU for much faster inference.

NVIDIA (CUDA)

  1. Install the NVIDIA driver from nvidia.com/drivers
  2. Install CUDA Toolkit 12.x
  3. Edit config.yaml:
ai:
  server:
    n_gpu_layers: 999    # 0 = CPU, 999 = all layers on GPU

Then restart the server.

AMD (ROCm)

Install ROCm 5.6+ and set n_gpu_layers: 999.

Apple Silicon

Works out of the box — Metal is enabled automatically.

Frequently Asked Questions #

Does this work without internet?

Yes. After the initial setup.py run, everything works offline. You can download additional packages and models manually if needed.

Do I need Python installed on my system?

Only to run setup.py itself (Python 3.9+). After that, everything uses the portable Python inside the project folder.

Can I move the project folder to another location?

Yes. All paths are relative. Move the folder anywhere — even to another drive or operating system — and everything still works.

How do I add a new Python package?

from toolkit.maintenance import install_python_package
install_python_package("statsmodels")

How do I add a new DuckDB extension?

from toolkit.maintenance import install_duckdb_extension
install_duckdb_extension("spatial")
install_duckdb_extension("qvd", community=True)

How do I change the AI model?

from toolkit.maintenance import change_ai_model
change_ai_model("qwen2.5-7b")

Can I use this on a server with limited permissions?

Yes. The toolkit never touches system files or requires admin rights. Everything lives inside the project folder.

What if I want to use it on Linux?

Works identically. Use the .sh launchers instead of .bat. See docs/INSTALL_LINUX.md for details.

How do I uninstall?

Just delete the project folder. Nothing was installed on your system.

Troubleshooting #

"No module named 'toolkit'"

Make sure you selected the correct kernel:

  1. In JupyterLab, click the kernel selector in the top-right
  2. Choose DuckDB Toolkit (portable)
  3. Kernel menu → Restart Kernel

"DuckDB extensions: 0 found"

Extensions are stored under a version-specific folder. Run:

python setup.py

Then re-run python verify.py.

Port already in use

Jupyter uses port 8888 by default. If it's taken:

runtime\python\python.exe -m jupyterlab --port 8889

Browser doesn't open automatically

Copy the URL from the terminal and paste it in your browser. Make sure to include the token.

AI server won't start

  1. Check if port 8080 is free
  2. Verify the model exists: runtime/models/qwen2.5-1.5b-instruct-q4_k_m.gguf
  3. Run python setup.py to redownload

Whisper model download fails

Whisper models are stored in ~/.cache/whisper/. To download manually:

import whisper
whisper.load_model("small")

Extension install fails on Windows

Some community extensions don't have Windows builds yet. The setup continues anyway, and other extensions still work.
